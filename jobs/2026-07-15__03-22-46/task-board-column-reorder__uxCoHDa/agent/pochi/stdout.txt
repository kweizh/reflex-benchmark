Cards are persisted in a local SQLite database with an explicit integer ordering index, and users reorder cards using buttons only (no drag-and-drop), so behavior is fully deterministic. ## Requirements * A single page at route `/` renders the three columns side by side with their cards, ordered from top to bottom. * Cards are stored in SQLite using a Reflex database model (`rx.Model`, `table=True`). Each card record has at least these fields: * `title`: the card text (string). * `status`: which column the card is in, one of exactly `"todo"`, `"doing"`, `"done"`. * `position`: a 0-based integer ordering index that is **contiguous within each column** (a column with N cards uses positions `0..N-1`, with no gaps or duplicates), and cards are displayed in ascending `position` order within their column. * The first time the app loads and the card table is empty, seed it (once) with exactly these cards, in this order per column: * To Do: `Write spec` (position 0), `Design schema` (position 1), `Draft tests` (position 2) * Doing: `Build API` (position 0), `Wire UI` (position 1) * Done: `Kickoff meeting` (position 0) * Each card provides four move buttons implemented as server-side event handlers that take the card's database id as an argument: * **Move right**: advance the card one column along the order `todo -> doing -> done`. Remove it from its current column (compacting the remaining cards so their positions stay contiguous) and append it to the end of the target column (its new position equals the number of cards already in the target column). If the card is already in `done`, this is a no-op. * **Move left**: the mirror of move right along `done -> doing -> todo`; append to the end of the target column. If already in `todo`, it is a no-op. * **Move up**: swap the card's position with the card directly above it in the same column. If the card is already at the top (position 0), it is a no-op. * **Move down**: swap the card's position with the card directly below it in the same column. If the card is already at the bottom of its column, it is a no-op. * Every move must update the SQLite ordering indexes inside a single database session/transaction and commit the change so it persists across page reloads and server restarts. After any move, the positions in every affected column must remain a contiguous, gap-free 0-based sequence. * Show a live per-column card count for each column, computed on the backend using Reflex computed vars (`@rx.var`).
