## What was implemented

**State (`EditorState`)**
- `content` — synchronized base var holding the currently committed content (starts empty).
- `input_value` — synchronized base var bound to the text input.
- `_undo_stack` / `_redo_stack` — backend-only (underscore-prefixed) lists of string snapshots. They are never serialized to the browser; only derived computed values are sent.

**Event handlers**
- `commit()` — pushes the previous content onto the undo stack, sets the new content to the input value, clears the redo stack, and enforces the 50-entry bound on the undo stack (drops oldest when exceeded).
- `undo()` — pushes the pre-undo current content onto the redo stack and restores the last value from the undo stack (no-op when the undo stack is empty).
- `redo()` — pushes the pre-redo current content back onto the undo stack (also bounded to 50) and re-applies the last value from the redo stack (no-op when empty).
- `set_input()` — keeps the input box in sync.

**Computed vars (`@rx.var`)**
- `can_undo` / `can_redo` — booleans derived from the backend-only stacks.
- `undo_disabled` / `redo_disabled` — drive the buttons' `disabled` prop so each button is disabled exactly when its action isn't possible.
- `history_label` — produces exactly `Undo depth: <u> | Redo depth: <r>`.

**UI (single page at `/`)**
- A text input bound to `input_value`.
- `Commit`, `Undo`, and `Redo` buttons (Undo/Redo disabled reactively).
- An element with `id="content-display"` showing the current committed content.
- An element with `id="history-label"` showing the history-depth label.

Initial state is the empty string with both stacks empty, so both buttons start disabled and the label reads `Undo depth: 0 | Redo depth: 0`.

To run it manually: `cd /home/user/editor && uv run reflex run` (frontend on 3000, backend on 8000).
