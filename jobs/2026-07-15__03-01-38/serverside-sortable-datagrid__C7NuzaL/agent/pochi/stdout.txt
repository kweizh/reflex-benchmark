# Server-Side Sortable Employee Data Grid (Reflex) ## Background You are building a data-management console with the **Reflex** Python web framework. The console shows an employee directory backed by a local SQLite database. Because the dataset is large, all pagination, sorting, and filtering must be performed **server-side** (in SQL), not in the browser. The application must also expose a small JSON API on the backend that runs the exact same server-side query, so the query engine can be exercised programmatically. Reflex compiles a declarative Python UI into a React frontend (port 3000) served alongside a FastAPI backend (port 8000) that holds the application State. ## Requirements * Build a Reflex application whose home page (`/`) renders an employee data grid with columns for `id`, `name`, `department`, `salary`, and `active`. * The grid must support, all computed on the server against SQLite: * **Server-side pagination**: a configurable page and page size (default page size 10), with Previous/Next controls. * **Multi-column sorting**: clicking a column header toggles that column between ascending and descending and adds it to an ordered list of sort keys, so multiple columns can be sorted at once. Each sorted header must show an ascending/descending indicator. * **Column filters**: filter by department (exact match), by a minimum salary, and by a case-insensitive substring of the name. * The data-loading event handler must be an **async background event** that opens an async database session (`rx.asession`) and builds the SQL query dynamically from the current pagination, sort, and filter state. * Use **computed vars** to derive the total number of pages and a page label, and display the page label (formatted exactly as `Page <page> of <total_pages>`) in the UI. * Seed the database deterministically on startup (see below) so the grid always has data. * Expose a backend JSON API endpoint (served by the Reflex FastAPI backend on port 8000) that performs the identical server-side query and returns the results as JSON. ## Seed Data (exact, deterministic) On startup, if the employee table is empty, insert exactly 24 employees. For each `i` from 1 to 24 (inserted in ascending `i` order so that the auto-increment `id` equals `i`): * `name` = `Employee NN` where `NN` is `i` zero-padded to 2 digits (e.g. `Employee 01`, `Employee 24`). * `department` = element `(i - 1) % 4` of the list `["Engineering", "Sales", "Marketing", "Support"]`. * `salary` = `50000 + ((i * 37) % 100) * 100` (an integer). * `active` = `True` when `i % 5 != 0`, otherwise `False`. Seeding must be idempotent: do not duplicate rows if the table already has data. ## API Contract `GET /api/employees` on `http://localhost:8000` accepts these query parameters (all optional): * `page`: 1-based page number, default `1`. * `page_size`: rows per page, default `10`. * `sort`: comma-separated list of `field:direction` tokens applied in order, where `field` is one of `id`, `name`, `department`, `salary` and `direction` is `asc` or `desc` (e.g. `department:asc,salary:desc`). When omitted, order by `id` ascending. * `department`: exact-match filter on department. * `min_salary`: integer; keep only rows whose salary is greater than or equal to this value. * `name_contains`: case-insensitive substring filter on name. Filters combine with logical AND. The response is HTTP 200 with a JSON object whose keys are exactly `page`, `page_size`, `total`, `total_pages`, `page_label`, and `rows`: * `total` is the number of rows matching the filters, before pagination. * `total_pages` is `max(1, ceil(total / page_size))`. * `page_label` is the string `Page <page> of <total_pages>`. * `rows` is the filtered, sorted result sliced to the requested page (offset `(page - 1) * page_size`, limit `page_size`). Each element is an object whose keys are exactly `id`, `name`, `department`, `salary`, `active`. ## Implementation Hints * Project path: `/home/user/employee_grid` * Manage the Python environment with `uv`. Initialize the project non-interactively with the blank template, add `reflex` and the async SQLite driver `aiosqlite`, then create the schema with the Reflex database migration commands before running. * `rx.asession` requires an async database URL: configure both `db_url` (e.g. `sqlite:///reflex.db`) and `async_db_url` (e.g. `sqlite+aiosqlite:///reflex.db`) in `rxconfig.py` so they point at the same file. * Define the employee table as a subclass of `rx.Model` with `table=True`. * Never build SQL with string formatting of user input; use the ORM/query builder to add `where`, `order_by`, `offset`, and `limit` clauses. * Extend the backend with the JSON API by passing a FastAPI app via the `api_transformer` parameter of `rx.App`. Sharing one query helper between the State background handler and the API route keeps their results identical. * Start command (run from the project directory): `uv run reflex run` * Ports: frontend `3000`, backend `8000`. * After you finish building and verifying, you MUST kill every background server or process you started (for example the `reflex run` dev server) so no process keeps listening on ports 3000 or 8000.
