# Kanban Task Board with Button-Based Reordering (Reflex) ## Background Build a Kanban-style task board as a full-stack web app using the https://reflex.dev Python framework. The board has three fixed columns rendered left-to-right: **To Do**, **Doing**, and **Done**. Each column holds an ordered list of cards. Cards are persisted in a local SQLite database with an explicit integer ordering index, and users reorder cards using buttons only (no drag-and-drop), so behavior is fully deterministic. ## Requirements * A single page at route `/` renders the three columns side by side with their cards, ordered from top to bottom. * Cards are stored in SQLite using a Reflex database model (`rx.Model`, `table=True`). Each card record has at least these fields: * `title`: the card text (string). * `status`: which column the card is in, one of exactly `"todo"`, `"doing"`, `"done"`. * `position`: a 0-based integer ordering index that is **contiguous within each column** (a column with N cards uses positions `0..N-1`, with no gaps or duplicates), and cards are displayed in ascending `position` order within their column. * The first time the app loads and the card table is empty, seed it (once) with exactly these cards, in this order per column: * To Do: `Write spec` (position 0), `Design schema` (position 1), `Draft tests` (position 2) * Doing: `Build API` (position 0), `Wire UI` (position 1) * Done: `Kickoff meeting` (position 0) * Each card provides four move buttons implemented as server-side event handlers that take the card's database id as an argument: * **Move right**: advance the card one column along the order `todo -> doing -> done`. Remove it from its current column (compacting the remaining cards so their positions stay contiguous) and append it to the end of the target column (its new position equals the number of cards already in the target column). If the card is already in `done`, this is a no-op. * **Move left**: the mirror of move right along `done -> doing -> todo`; append to the end of the target column. If already in `todo`, it is a no-op. * **Move up**: swap the card's position with the card directly above it in the same column. If the card is already at the top (position 0), it is a no-op. * **Move down**: swap the card's position with the card directly below it in the same column. If the card is already at the bottom of its column, it is a no-op. * Every move must update the SQLite ordering indexes inside a single database session/transaction and commit the change so it persists across page reloads and server restarts. After any move, the positions in every affected column must remain a contiguous, gap-free 0-based sequence. * Show a live per-column card count for each column, computed on the backend using Reflex computed vars (`@rx.var`). The counts must update reactively after every move. ## Implementation Hints * Use `uv` to manage the Python environment. Initialize the project non-interactively, e.g. `uv init`, `uv add reflex`, `uv run reflex init --template blank`, then set up the database schema with `uv run reflex db init`, `uv run reflex db makemigrations --message "initial schema"`, and `uv run reflex db migrate`. Commit the generated migration files so the schema can be recreated on a fresh database. * Persist data with `rx.Model` and perform reads/writes inside `rx.session()`; wrap each reorder in one transaction and call `commit()`. * Derive the per-column counts with cached computed vars and render the card lists with `rx.foreach` (one foreach per column). * Reorder handlers should accept the card id as an event argument (bind with a lambda or partial event args), mutate the DB, then reload the state's card list from the database so the UI and computed vars refresh. * The database is the default local SQLite database (`sqlite:///reflex.db`) created in the project directory; no external services, network calls, or secrets are involved. * Project path: `/home/user/task_board` * Start command (run from the project path): `uv run reflex run` * Ports: frontend on `3000`, backend on `8000`. ### Frontend contract (required so the UI can be verified) The rendered page MUST expose the following stable hooks: * Per-column count element: an element with attribute `data-testid` equal to `count-todo`, `count-doing`, and `count-done` respectively, whose visible text is exactly the integer count of cards in that column. * Each card's four move buttons must set `data-testid` to, respectively, `move-left-<id>`, `move-right-<id>`, `move-up-<id>`, and `move-down-<id>`, where `<id>` is that card's database primary-key id. (Set custom attributes on the components, e.g. via `custom_attrs`.) * Each card must also display its `title` text somewhere in the card. ### Cleanup This app runs a development server in the background during your work. Before you finish, you MUST stop/kill every background server or process you started (both the Reflex frontend on port 3000 and backend on port 8000) so that no server is left running after your task is complete. The verifier will start its own server.
